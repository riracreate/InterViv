- **Manual Follow-Ups (Preserved Fallback)**: Candidates can still invoke `POST /session/{id}/follow-ups` (`backend/routes/follow_ups.py:27-100`) with `window.confirm` (`Interview.jsx:1509-1540`). ## 3. Answer-Aware Follow-Up Selection & Round-Index Integrity (`Q2`, `A4–A6`)

- **Bundle Status Policy (`A4`)**: Never serve bundles with status `generated` or `rejected` to a candidate. In `coached_practice`, bundle selection floors at `auto_checked` (`reviewed` > `auto_checked`); when `REVIEWED_BUNDLES_ONLY=true`, `reviewed` only. Currently `REVIEWED_BUNDLES_ONLY` defaults to **`False`** at `backend/config.py:138` (`reviewed_bundles_only=_env_bool("REVIEWED_BUNDLES_ONLY", False)`) and `.env.example:29`.
- **Gap Matching & Zero Live LLM Calls (`Q2`)**: Candidate scoring (`Scorer v3`; `concept_evaluator_v3` remains restricted to `bundle_generator.py:1541` checks) produces concept trace diagnostics (`question_concepts.py:155-236` via `concept_evaluator_v2` on bundle `required_concepts`). Inside `modules/follow_ups.py`:
  1. Prioritize gaps strictly as **`contradicted` > `missing`** (`not_demonstrated` / `missed`). **Ignore `uncertain` concepts**.
  2. Look up structured `followups[]` from stored `question_bundle_versions` (`reviewed` or `auto_checked` only — never `generated` or `rejected`) using `(bundle_id, version)` pinned on the parent round; select the first follow-up whose `targets_concept` matches a `contradicted` or `missing` gap.
  3. **No fallback**: if there are zero `contradicted`/`missing` gaps, or no bundle follow-up matches those gaps, **schedule nothing** (never fall back to `followups[0]`).
- **Inline Insertion Inside `/session/answer` & Round-Index Handling (`A5`)**: Decide and splice the inline follow-up inside `POST /session/answer`'s atomic commit loop **before** `session_status` / round `n+1` preparation (`backend/routes/answer.py:1288-1325`):
  - **`expanded_plan` JSON (`SessionRow.expanded_plan_json`)**: Entries `<= n` (`parent_round`) stay untouched. Splice `{follow_up_entry, "round": n + 1}` at index `parent_round`, shift **only unprepared subsequent plan entries** (`round >= n + 1` with no row in `rounds`) by `+1` (`entry["round"] += 1`), and increment `total_rounds` by `+1`. Under `SessionWriteConflict` retries (`answer.py:1201-1230`), re-running against the reloaded `session` checks `parent_already_has_follow_up` (`modules/follow_ups.py:117-130`) so duplicate follow-ups are never inserted.
  - **`RoundRow` (`rounds` table, `sqlalchemy_models.py:172-235`)**: Existing rows `1..n` keep immutable `round_number`s (`test_sql_allocation_preserves_round_row_identities` invariant). Because round `n+1` has not been built yet, preparing `next_round = n + 1` creates the new `ready` `RoundRow` directly as the follow-up at `round = n + 1`, and later mandatory turns materialize as `n + 2, n + 3...` sequentially.
  - **`bundle_jobs` (`modules/bundle_jobs.py:53-62`)**: Deterministic key `bjob:{skill}:{topic}:{difficulty}` is independent of `round_number` (`session_id` is informational only), so shifting unprepared plan rounds cannot desync prefetch jobs.
  - **`narration_jobs` (`modules/narration_jobs.py:40-43`)**: Key `f"{session_id}:{round_number}:narration"` is created inside `/session/answer` **after** submission (`answer.py:1671`). Committed rounds `1..n` keep their keys; future rounds have no narration job until submitted.
  - **`feedback` (`backend/routes/feedback.py:128-200`) & `activation` (`backend/routes/round_activation.py:45-96`) routes**: Both look up `round` directly in `rounds` (`feedback.py:148-154`, `round_activation.py:79-83`); `answer_drafts` clears keyed on committed `request.round` (`n`). `/activate` opens follow-up `n+1` (`ready -> in_progress`), and `/feedback` reads committed round `n` cleanly.
  - **Frontend round counter (`Interview.jsx:1264`)**: Displays `Question {round} / {totalRounds}` from `answerResp.next_round` and `answerResp.total_rounds` (`answer.py:1813,1825`); updated `total_rounds` stays accurate in Slice 1, and Slice 3 `StageRail` separates stage labels from follow-up turns.
- **Decision Logging (`A6`)**: Every inline follow-up decision (triggered or skipped) records `{session_id, parent_round, bundle_id, version, bundle_status, practice_mode, gap_concept, gap_status, decision, reason, chosen_prompt}` to structured Python logging, `round_meta`/session audit metadata, and JSONL audit log (`FOLLOWUP_DECISIONS_AUDIT_PATH`, defaulting under `artifacts/followup_decisions_audit.jsonl`) for human review.

## 6. Scoring, Deferred Feedback & Follow-Up Outcomes (`Q1`, `Q3`, `Q4`, `A7–A9`)

- **Pinned to `Scorer v3`**: `modules/scoring_schema.py` keeps `v3` default (`v4` stays OFF behind `SCORER_VERSION=v4`; `v1–v3` baselines/hash locks untouched). `concept_evaluator_v3` stays isolated in `bundle_generator.py:1541` checks and is never used in candidate scoring.
- **Deferred Feedback Rule (`A7` / `Q1`, `F2` reason)**: In `staged_v1`, all per-round feedback and scores are deferred to the Debrief — the client makes **no** `GET /session/{id}/rounds/{n}/feedback` calls and displays no score until the session is complete. *Reason (`F2`)*: `GET /rounds/{n}/feedback` records `feedback_reveal` (`backend/routes/feedback.py:176-187`) whose `topic_scope_for_round` (`scope_certainty="topic"` when `question_context` omits `required_concepts`) marks subsequent Core rounds on the same skill/topic (and Core 1 after a same/un-topicked Warm-up) as `excluded` (`coarse_topic_scope`) without altering `assistance_policy`.
- **Follow-Up Outcome Rule (`A8` / `Q2`)**: Inline bundle follow-ups hide the numeric score from the candidate (`final_score = null` in `/session/answer`, `/feedback`, narration scripts, and `/dashboard`) and show only the targeted concept's label and whether the follow-up answer demonstrated it (no parent-rubric `"very brief"` / `"lacked keywords"` messages). Raw `v3` diagnostics may stay in server-side `scoring_breakdown` for analysis only and are never returned to the client. Manual `/follow-ups` and all other rounds remain unchanged.
- **Known Limitation (`A9` / `F3`)**: Bundle selection ignores `target_concepts`, so adaptive concept targeting (`ConceptMastery`) does not apply to bundle questions.
- **Single Score & Anti-Leak**: UI shows only `final_score` (at Debrief / non-follow-up measured rounds) and allowlisted feedback (`feedback.py:38-45`); internal layer scores and references remain hidden until completion (`feedback.py:91-99`).
- **Exclusions (`Q1`, `Q3`, `Q4`)**: **Follow-ups** (`is_follow_up = True`, `modules/assistance_policy.py:298-305`), **Warm-up** (`final_score = None`), and **Behavioural (`HR`, question text only, unscored)** (`final_score = None`) **never enter `assessment_eligible_scores`** (`backend/evidence_kind.py:158-188`) or move **Elo**.

## 8. Offline Behaviour (Live Calls Off — Default)

With `llm_live_fetch_enabled()` off (default): `_inline_bundle_generation_enabled()` and `_background_bundle_prefetch_enabled()` return `False` (`session.py:1402-1422`), and `NullNarrationProvider` is active (`narration_provider.py:113`).
- **Warm-up** serves unscored `easy` CSV/fallback prompt even if `REVIEWED_BUNDLES_ONLY=true`; **Core** selects `reviewed` / `auto_checked` bundles (never `generated`/`rejected` per `A4`), falling back to `interview_dataset_v6.csv` / `fallback_question_bank.csv` / `_TEMPLATES` when `REVIEWED_BUNDLES_ONLY=false`.
- **Follow-ups** select matching `targets_concept` prompts strictly for `contradicted`/`missing` gaps on `reviewed`/`auto_checked` bundles with zero live LLM calls (no match -> no follow-up).
- **Practical** runs local SQL/Coding/SystemDesign; **Behavioural** serves unscored, question-text-only `HR` prompts from `data/behavioural_questions_v1.csv`, built from approved `artifacts/hr_questions_reviewed.csv` by `build_behavioural_questions_csv`, with `StarComposer.jsx`. Behavioural is **skipped when the compiled bank is absent**; raw dataset rows are not an automatic substitute. **Debrief** serves deterministic rules feedback (`narration.status = "skipped"`, `feedback.py:81-84`) and `/dashboard/{sessionId}`.

## 9. Build Slices in Order & Explicit Out-of-Scope (`A1–A6`)

1. **Slice 1 — Inline Bundle Follow-Ups (Gated Off by Default)**: Add opt-in setting (`STAGED_INLINE_FOLLOW_UPS`, default `False`), `auto_checked` floor (no `generated`/`rejected` serving per `A4`), automatic inline follow-up decision inside `POST /session/answer` atomic write (`contradicted > missing` only, no `uncertain`, no `followups[0]` fallback per `Q2`), splice at `parent + 1` shifting only unprepared plan entries (`A5`), decision logging (`A6`), and manual `/follow-ups` untouched.
2. **Slice 1b — Inline Follow-Up Outcome (`A8`), Minimal Follow-Up UI & Deferred-Feedback Verification (`A7`)**: Suppress candidate-facing `final_score`, parent-rubric messages, score narration, and raw `scoring_breakdown` on inline follow-ups (`final_score = null`, targeted-concept demonstration outcome only); surface `Follow-up` badge / hide `"Request optional follow-up"` / hide `%` in existing `Interview.jsx`; add 3-core-round deferred-feedback readiness test.
3. **Slice 2 — Presets, Practical Optionality, Warm-up & Unscored `HR` (No Schema Change per `A1`)**: Wire `Quick` (~15m) & `Full` (~45–50m) presets (`A3`), role-based Practical skipping (`A2`), `easy` unscored Warm-up (`Q1`), and question-text-only unscored `HR` Behavioural stage (`Q4`, after review of `artifacts/hr_questions_review.csv`) using existing JSON columns only.
4. **Slice 3 — Separate Staged Screen & Presets**: Route `staged_v1` sessions through new staged component files, including `StageRail`, `ConversationThread`, and `StagedDebriefCard`; add `Quick`/`Full` launcher cards in `Practice.jsx`. Keep `Interview.jsx` unchanged for non-staged sessions. Scores/feedback remain deferred until completion (`A7`); the committed `docs/design/slice3_ui_plan.md` will define the session-sized sub-slices. Build only after reviewer approval of that plan.

- **Explicitly OUT of Scope**: Alembic migrations / DB schema changes (`A1`), voice / STT / TTS changes, whiteboard/drawing canvas, auth (`auth.py` / JWT), DB engine changes, `scripts/local_runner.py` / `scripts/run_local.py` modifications, and scorer `v1–v4` modifications.
